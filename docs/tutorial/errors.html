Errors & Warnings

FunLang provides detailed error messages with source locations and hints. This page documents all error types and pattern matching warnings.

Error Message Format

FunLang uses Rust-style error messages:

error[E001]: Unexpected character: @
  --> file.fun:1:1
  |
1 | @bad
  | ^
   = info: character not recognized by lexer

Components:

  • Error code (e.g., E001) - Unique identifier
  • Message - Description of the error
  • Location - File, line, and column
  • Source snippet - The problematic code with pointer
  • Hint - Suggestion for fixing the error

Pattern Matching Warnings

FunLang analyzes pattern matches for completeness and usefulness. These are warnings, not errors - the program will still run.

Non-Exhaustive Pattern Warning

Warns when pattern matching might fail at runtime because not all cases are covered.

Code
type Option 'a = None | Some of 'a

let getValue = fun opt ->
  match opt with
  | Some x -> x
Warning
Warning: Non-exhaustive pattern match at line 4, column 3
  Missing case(s): None

How to Fix

Option 1: Handle all cases explicitly

let getValue = fun opt ->
  match opt with
  | Some x -> x
  | None -> 0    // handle None case

Option 2: Use wildcard as catch-all

let getValue = fun opt ->
  match opt with
  | Some x -> x
  | _ -> 0        // wildcard catches None

Common Cases

TypeMissing Pattern ExampleFix
bool | true -> ... Add | false -> ...
list | h :: t -> ... Add | [] -> ...
Option | Some x -> ... Add | None -> ...

Redundant Pattern Warning

Warns when a pattern can never be matched because previous patterns already cover all cases.

Code
let test = fun x ->
  match x with
  | true -> 1
  | false -> 2
  | true -> 3   // this pattern is redundant!
Warning
Warning: Pattern 3 at line 5, column 5 is redundant (never matches)

How to Fix

Remove the redundant pattern:

let test = fun x ->
  match x with
  | true -> 1
  | false -> 2

Wildcard Redundancy

Code
let test = fun x ->
  match x with
  | _ -> 1           // matches everything
  | true -> 2        // redundant!
  | false -> 3       // redundant!
Warning
Warning: Pattern 2 at line 4, column 5 is redundant (never matches)
Warning: Pattern 3 at line 5, column 5 is redundant (never matches)
Note
Place wildcards (_) and catch-all patterns last in your match expressions.

Pattern Analysis for Lists

Non-exhaustive list pattern
let head = fun xs ->
  match xs with
  | h :: _ -> h
Warning: Non-exhaustive pattern match
  Missing case(s): []
Fixed version
let head = fun xs ->
  match xs with
  | h :: _ -> h
  | [] -> 0        // or use Option type

Pattern Analysis for Custom Types

Missing constructor
type Color = Red | Green | Blue

let toHex = fun c ->
  match c with
  | Red -> "#FF0000"
  | Green -> "#00FF00"
Warning: Non-exhaustive pattern match
  Missing case(s): Blue

Best Practices

Pattern Matching Tips
  • Always handle all constructors of algebraic types
  • Use wildcards last as catch-all patterns
  • Handle empty list [] for list patterns
  • Handle both true and false for bool patterns
  • Pay attention to warnings - they prevent runtime errors
