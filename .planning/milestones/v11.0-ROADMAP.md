# Milestone v11.0: Typed AST Export

**Status:** ✅ SHIPPED 2026-04-03
**Phases:** 79-82
**Total Plans:** 5

## Overview

Export HM type inference results — per-expression annotation map and top-level binding environment — so FunLangCompiler can replace ~250 lines of heuristic type-guessing code with accurate type information.

**Motivation:** ohama/FunLang#3, ohama/FunLang#4

## Phases

### Phase 79: Type Annotation Infrastructure

**Goal**: Per-expression type annotation map exists and is populated during type checking
**Depends on**: Phase 78 (v10.1 complete)
**Requirements**: TA-01, TA-02
**Plans**: 2 plans

Plans:
- [x] 79-01: Define TypeAnnotationMap module, declare mutable ref, wire resets
- [x] 79-02: Wire annotation recording into every Bidir.synth arm + tests

**Details:**
- Created TypeAnnotationMap.fs with ConcurrentDictionary<Span, Type> and create/record/tryFind/toSeq helpers
- Declared mutable annotationMap in Bidir.fs following established mutableVars/pendingConstraints pattern
- 65 recordTy call sites covering all 52 Expr variants in synth + GADT check arm
- 7 TypeAnnotation tests (TA-01 through TA-07)

### Phase 80: Type Environment Export

**Goal**: Top-level binding types (user-defined and builtin/prelude) are accessible as a named collection
**Depends on**: Phase 79
**Requirements**: TE-01, TE-02
**Plans**: 1 plan

Plans:
- [x] 80-01: Add BindingEnv alias + exportBindingEnv helper, TypeEnvTests for TE-01/TE-02

**Details:**
- type BindingEnv = TypeEnv alias and exportBindingEnv identity helper in TypeCheck.fs
- 9 TypeEnvTests covering user bindings, all builtins, queryability

### Phase 81: Export API

**Goal**: External callers can type-check a FunLang file and receive a single TypedModule record
**Depends on**: Phase 80
**Requirements**: API-01, API-02
**Plans**: 1 plan

Plans:
- [x] 81-01: Implement ExportApi.fs with TypedModule record, typeCheckFile entry point, and tests

**Details:**
- ExportApi.typeCheckFile wires loadPrelude -> parse -> typeCheckModuleWithPrelude -> snapshot
- TypedModule record: AnnotationMap (Map<Span,Type>), BindingEnv, BuiltinSchemes
- 5 ExportApi tests

### Phase 82: CLI Integration

**Goal**: Users can invoke --emit-typed-ast on any FunLang file and receive JSON type information on stdout
**Depends on**: Phase 81
**Requirements**: CLI-01
**Plans**: 1 plan

Plans:
- [x] 82-01: Add --emit-typed-ast flag, JSON serialization, and flt tests

**Details:**
- Emit_Typed_Ast in Cli.fs, serializeTypedModule in Program.fs via System.Text.Json.Nodes
- JSON: {"annotations":[{span, type}], "bindings":{name: scheme}}
- Filtered to user-file spans and user bindings only
- 2 flt integration tests

## Milestone Summary

**Key Decisions:**
- ConcurrentDictionary for annotationMap (parallel test safety)
- TypeAnnotationMap.record skips unknownSpan (elaborated typeclass nodes)
- BindingEnv = TypeEnv identity alias
- ExportApi raises on error (matches codebase style)
- System.Text.Json.Nodes for JSON (no new NuGet packages)

**Issues Deferred:**
- 3 low-severity typeclass bugs from v10.1
- parseModuleFromString duplication (3rd copy in ExportApi.fs)
