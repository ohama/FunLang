Building FunLang

This guide covers how to build, run, and develop FunLang from source.

Requirements

Required

  • .NET 9.0 SDK or later

Included Dependencies

These are automatically restored by dotnet restore:

  • FsLexYacc - Lexer/Parser generator (F# port of lex/yacc)
  • Argu - Command-line argument parsing
  • Serilog - Structured logging
  • Expecto + FsCheck - Testing framework

Build Commands

Basic Build

# Clone the repository
git clone https://github.com/your-repo/FunLang.git
cd FunLang

# Restore dependencies
dotnet restore

# Build the project
dotnet build

# Verify build succeeded
dotnet run --project src/FunLang -- --version

Build Configurations

CommandDescription
dotnet buildDebug build (default)
dotnet build -c ReleaseRelease build (optimized)
dotnet cleanClean build artifacts
dotnet restoreRestore NuGet packages

Publish (Standalone Binary)

# Create a self-contained executable
dotnet publish -c Release -r linux-x64 --self-contained

# Or for other platforms:
dotnet publish -c Release -r win-x64 --self-contained
dotnet publish -c Release -r osx-x64 --self-contained
dotnet publish -c Release -r osx-arm64 --self-contained

Running FunLang

Development Mode

# Run a file
dotnet run --project src/FunLang -- myprogram.fun

# Evaluate an expression
dotnet run --project src/FunLang -- -e "1 + 2 * 3"

# Interactive REPL
dotnet run --project src/FunLang -- -i

After Publishing

# The executable will be in:
./bin/Release/net9.0/linux-x64/publish/FunLang

# Run directly
./FunLang myprogram.fun
./FunLang -e "1 + 2"
./FunLang -i

Running Tests

All Tests

# Run all tests
dotnet test

# Or using Expecto directly (more options)
dotnet run --project tests/FunLang.Tests

Filtered Tests

# Filter by test list name (substring match)
dotnet run --project tests/FunLang.Tests -- --filter-test-list "Lexer"
dotnet run --project tests/FunLang.Tests -- --filter-test-list "Parser"
dotnet run --project tests/FunLang.Tests -- --filter-test-list "Type"
dotnet run --project tests/FunLang.Tests -- --filter-test-list "File-Based"

# Filter by test case name
dotnet run --project tests/FunLang.Tests -- --filter-test-case "fibonacci"
dotnet run --project tests/FunLang.Tests -- --filter-test-case "factorial"

Build Pipeline

FunLang uses FsLexYacc to generate the lexer and parser. The build pipeline:

# 1. FsYacc generates Parser.fs from Parser.fsy
Parser.fsy  →  Parser.fs

# 2. FsLex generates Lexer.fs from Lexer.fsl
Lexer.fsl   →  Lexer.fs

# 3. F# compiler compiles everything
*.fs        →  FunLang.dll
Important
Parser.fs must be compiled before Lexer.fs because the lexer references token types defined by the parser.

Development Workflow

Watch Mode

# Automatically rebuild on file changes
dotnet watch run --project src/FunLang -- myprogram.fun

Debug Mode

# Show all debug information
dotnet run --project src/FunLang -- -d myprogram.fun

# Show specific phases
dotnet run --project src/FunLang -- --show-tokens myprogram.fun
dotnet run --project src/FunLang -- --show-ast myprogram.fun
dotnet run --project src/FunLang -- --show-types myprogram.fun

Version Management

Use the version upgrade script to release new versions:

# Patch release: 0.5.0 → 0.5.1
./upgrade_version.sh patch

# Minor release: 0.5.0 → 0.6.0
./upgrade_version.sh minor

# Major release: 0.5.0 → 1.0.0
./upgrade_version.sh major

# With auto-push to remote
./upgrade_version.sh minor --push

The script automatically:

  1. Bumps version in VERSION file
  2. Generates changelog from git commits
  3. Updates CHANGELOG.md
  4. Creates git commit and tag (vX.Y.Z)
  5. Pushes to remote (with --push flag)

Troubleshooting

Parser/Lexer Not Regenerating

# Clean and rebuild
dotnet clean
dotnet build

Missing Dependencies

# Restore all packages
dotnet restore

Test Failures After Changes

# Run tests with verbose output
dotnet run --project tests/FunLang.Tests -- --debug
