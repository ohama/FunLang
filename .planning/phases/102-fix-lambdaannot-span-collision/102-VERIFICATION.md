## Summary

The fix is fully implemented and verified. The root cause was that nested `LambdaAnnot` nodes generated by desugaring multi-param annotated functions all shared the same span, causing `annotationMap` key collisions. The fix threads a per-parameter `Span` (from `ruleSpan parseState 1 5`) through both `desugarAnnotParams` and `desugarMixedParams`, giving each `LambdaAnnot` node a unique span derived from its token positions in the source. All 245 unit tests (including new TA-08) and 726 flt tests pass.
