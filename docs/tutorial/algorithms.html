Implementation Algorithms

This section explains the key algorithms used in FunLang's implementation. Understanding these algorithms provides insight into how the language works internally.

Hindley-Milner Type Inference

FunLang uses the Hindley-Milner (HM) type system with Algorithm W for type inference. This allows the compiler to automatically infer types without explicit annotations.

Key Features

  • Type inference - No type annotations required
  • Let-polymorphism - Functions can be polymorphic
  • Principal types - The most general type is always inferred
  • Decidable - Type inference always terminates

Type Definitions

Monotype (Simple Types)

// Monotype grammar
τ ::= int                    -- Integer type
    | bool                   -- Boolean type
    | string                 -- String type
    | unit                   -- Unit type
    | α                      -- Type variable
    | τ₁ → τ₂                -- Function type
    | list τ                 -- List type
    | (τ₁, τ₂, ...)          -- Tuple type

Polytype (Type Schemes)

// Polytype (quantified type)
σ ::= τ                      -- Monotype
    | ∀α₁...αₙ. τ            -- Quantified type

// Examples:
∀α. α → α             // identity function type
∀α. list α → int       // length function type

Core Operations

1. Substitution

A mapping from type variables to types:

S = [α₁ ↦ τ₁, α₂ ↦ τ₂, ...]

// Application rules:
S(int) = int
S(α) = S(α) if α ∈ dom(S), else α
S(τ₁ → τ₂) = S(τ₁) → S(τ₂)
S(list τ) = list S(τ)

// Composition:
(S₁ ∘ S₂)(τ) = S₁(S₂(τ))

2. Free Type Variables

FV(int) = ∅
FV(α) = {α}
FV(τ₁ → τ₂) = FV(τ₁) ∪ FV(τ₂)
FV(∀α.τ) = FV(τ) - {α}
FV(Γ) = ∪{FV(σ) | x:σ ∈ Γ}

3. Generalization

Convert a type to a type scheme by quantifying free variables not in the environment:

generalize(Γ, τ) = ∀α₁...αₙ.τ
  where {α₁,...,αₙ} = FV(τ) - FV(Γ)

4. Instantiation

Create a fresh instance from a type scheme:

instantiate(∀α₁...αₙ.τ) = [α₁↦β₁,...,αₙ↦βₙ]τ
  where β₁,...,βₙ are fresh type variables

Unification Algorithm

Finds a substitution that makes two types equal:

unify : Type → Type → Result<Substitution, Error>

// Rules:
unify(α, τ) =
    if α = τ then ∅
    else if α ∈ FV(τ) then Error "occurs check"
    else [α ↦ τ]

unify(τ, α) = unify(α, τ)

unify(int, int) = ∅
unify(bool, bool) = ∅
unify(string, string) = ∅

unify(τ₁ → τ₂, τ₁' → τ₂') =
    S₁ = unify(τ₁, τ₁')
    S₂ = unify(S₁(τ₂), S₁(τ₂'))
    return S₂ ∘ S₁

unify(list τ, list τ') = unify(τ, τ')

unify(τ₁, τ₂) = Error "type mismatch" otherwise
Occurs Check

The occurs check prevents infinite types like α = list α, which would expand infinitely.

Algorithm W

The main type inference algorithm:

W : TypeEnv → Expr → Result<Substitution × Type, Error>

Inference Rules

Literals
W(Γ, n)     = (∅, int)      // integer literal
W(Γ, true)  = (∅, bool)     // boolean literal
W(Γ, false) = (∅, bool)
W(Γ, "s")   = (∅, string)   // string literal
W(Γ, ())    = (∅, unit)     // unit literal
Variables
W(Γ, x) =
    if x ∉ dom(Γ) then Error "unbound variable"
    else (∅, instantiate(Γ(x)))
Lambda Expressions
W(Γ, fun x -> e) =
    α = fresh type variable
    (S, τ) = W(Γ ∪ {x: α}, e)
    return (S, S(α) → τ)
Function Application
W(Γ, e₁ e₂) =
    (S₁, τ₁) = W(Γ, e₁)
    (S₂, τ₂) = W(S₁(Γ), e₂)
    α = fresh type variable
    S₃ = unify(S₂(τ₁), τ₂ → α)
    return (S₃ ∘ S₂ ∘ S₁, S₃(α))
Let Expressions (Polymorphism)
W(Γ, let x = e₁ in e₂) =
    (S₁, τ₁) = W(Γ, e₁)
    σ = generalize(S₁(Γ), τ₁)   // generalize here!
    (S₂, τ₂) = W(S₁(Γ) ∪ {x: σ}, e₂)
    return (S₂ ∘ S₁, τ₂)

Let-Polymorphism Example

Generalization in let enables polymorphism:

let id = fun x -> x in
(id 1, id true)    // OK: id is ∀α. α → α

Step-by-step:

  1. Infer id type: α → α
  2. Generalize: ∀α. α → α
  3. id 1: instantiate to β → β, unify with int, result: int
  4. id true: instantiate to γ → γ, unify with bool, result: bool
  5. Final type: (int, bool)

References

  • Damas, L., Milner, R. (1982). "Principal type-schemes for functional programs"
  • Pierce, B.C. (2002). "Types and Programming Languages"

Pattern Matching Analysis

FunLang implements Maranget's Usefulness algorithm for checking pattern matching exhaustiveness and redundancy.

Goals

  • Exhaustiveness - Warn if some values aren't matched
  • Redundancy - Warn if a pattern can never match

Pattern Representation

// Simplified pattern for analysis
type SimplePattern =
    | SPWildcard                                    // _ or variable
    | SPLiteral of Literal                          // 1, true, "str"
    | SPConstructor of string * SimplePattern list  // Name args
    | SPOr of SimplePattern list                    // For output

// Pattern row: a list of patterns (one per column)
type PatternRow = SimplePattern list

// Pattern matrix: list of rows
type PatternMatrix = PatternRow list

Usefulness Algorithm

A pattern vector is useful against a matrix if there exists a value that:

  • Matches the vector
  • Doesn't match any row in the matrix
let rec isUseful (matrix: PatternMatrix) (vector: PatternVector) : bool =
    match vector with
    // Base case: empty vector
    | [] -> matrix |> List.isEmpty

    // Empty matrix: any non-empty vector is useful
    | _ when List.isEmpty matrix -> true

    // Wildcard: check signature completeness
    | SPWildcard :: rest ->
        let headCtors = getHeadConstructors matrix
        if isComplete headCtors then
            // Check usefulness for each constructor
            allCtors |> List.exists (fun (name, arity) ->
                let matrix' = specialize name arity matrix
                let vector' = List.replicate arity SPWildcard @ rest
                isUseful matrix' vector')
        else
            // Incomplete: check default matrix
            isUseful (defaultMatrix matrix) rest

    // Constructor: specialize for this constructor
    | SPConstructor (name, args) :: rest ->
        let matrix' = specialize name (List.length args) matrix
        let vector' = args @ rest
        isUseful matrix' vector'

Matrix Operations

Specialize

Filter and expand the matrix for a specific constructor:

let specialize (ctor: string) (arity: int) (matrix: PatternMatrix) =
    matrix |> List.choose (fun row ->
        match row with
        | SPConstructor (name, args) :: rest when name = ctor ->
            // Matching: expand args
            Some (args @ rest)
        | SPWildcard :: rest ->
            // Wildcard: expand to `arity` wildcards
            Some (List.replicate arity SPWildcard @ rest)
        | _ ->
            // Non-matching: remove
            None)

Default Matrix

Keep only wildcard rows:

let defaultMatrix (matrix: PatternMatrix) =
    matrix |> List.choose (fun row ->
        match row with
        | SPWildcard :: rest -> Some rest
        | _ -> None)

Example: Exhaustiveness Check

Non-exhaustive Pattern
type Option 'a = None | Some of 'a

let getValue opt =
    match opt with
    | Some x -> x
    // Missing: | None -> ...
Warning: Non-exhaustive pattern match
  Missing case(s): None

Analysis:

  1. Matrix = [[Some _]]
  2. Check if [_] is useful against this matrix
  3. Constructors = {None, Some}
  4. None not in matrix head constructors
  5. Result: Non-exhaustive, missing None

Example: Redundancy Check

Redundant Pattern
match x with
| true -> 1
| false -> 2
| _ -> 3    // Redundant!
Warning: Pattern 3 is redundant (never matches)

Analysis:

  1. Build matrix incrementally: [[true]], then [[true], [false]]
  2. Check if [_] is useful against [[true], [false]]
  3. Bool has complete signature: {true, false}
  4. All constructors covered → wildcard not useful
  5. Result: Pattern 3 is redundant

References

  • Maranget, Luc (2007). "Warnings for Pattern Matching"

Indentation Processing

FunLang supports Python/Haskell-style significant indentation for block syntax.

Architecture

Source Code
    ↓
[Lexer (FsLex)] → Raw tokens with NEWLINE
    ↓
[Indentation Processor] → Tokens with INDENT/DEDENT
    ↓
[Parser (FsYacc)] → AST
    ↓
[Interpreter] → Value

State Machine

type IndentState = {
    IndentStack: int list    // Stack of column levels
    ParenDepth: int          // Nesting depth of () and []
    AtLineStart: bool        // Next token starts a line
    CurrentLine: int         // For error messages
}

Algorithm

For each token with position (tok, pos):

1. Handle NEWLINE token:
   if ParenDepth > 0 then skip
   else set AtLineStart = true

2. Handle other tokens:
   a. Update ParenDepth for ( ) [ ]
   b. if inside parens then emit token (no indent processing)
   c. if at line start then:
      col = pos.Column

      Case: col > stack.top
        → Push col onto stack
        → Emit INDENT, then token

      Case: col = stack.top
        → Emit NEWLINE (separator), then token

      Case: col < stack.top
        → Pop stack until col matches
        → Emit DEDENT for each pop, then token

3. At EOF:
   → Emit DEDENT for each level above base
   → Emit EOF

Block Transformation

The parser transforms indented blocks into nested let expressions:

Input
let x = 10
let y = 20
x + y
Transformed AST
ELet("x", 10, ELet("y", 20, x + y))

Parentheses Exception

Indentation is ignored inside parentheses and brackets:

let list = [
    1,
        2,    // indentation doesn't matter here
    3
]

AST Emit (Source Formatter)

The --emit (or -o) option parses source code into an AST and reformats it back to clean, consistently formatted source code.

Features

  • Consistent formatting - Standardized indentation and spacing
  • Comment preservation - Comments are maintained in output
  • Minimal parentheses - Only adds parentheses when necessary for precedence

Usage

# Format and display
funlang --emit messy.fun

# Format and save to file
funlang --emit clean.fun messy.fun
funlang -o clean.fun messy.fun

Pipeline

Source Code
    ↓
[Lexer] → Tokens + Comments (separate)
    ↓
[Parser] → AST (with position info)
    ↓
[Formatter] → Match comments to AST nodes
    ↓
Formatted Output (with comments)

Comment Preservation

Preserving comments during formatting is non-trivial because comments are not part of the AST.

Comment Buffer Mechanism

FsLex can only return one token at a time. To capture comments with the following NEWLINE token, a buffer mechanism is used:

// In Lexer.fsl
let mutable private commentBuffer: (string * int * int) option = None

// When // is encountered:
and lineComment startLine startCol acc = parse
    | newline {
        // Store comment in buffer
        commentBuffer <- Some (acc.ToString(), startLine, startCol)
        NEWLINE  // Return NEWLINE token
    }
    | _ {
        acc.Append(lexeme) |> ignore
        lineComment startLine startCol acc lexbuf
    }

Comment Classification

TypeConditionExample
Trailing Same line as code let x = 1 // comment
Leading Before code on next line // comment
let x = 1

Matching Algorithm

let rec formatWithComments indent expr comments =
    let exprLine = expr.Pos.Line

    // 1. Separate leading comments (before this expression)
    let (leading, remaining) =
        comments |> List.partition (fun c -> c.Pos.Line < exprLine)

    // 2. Separate trailing comment (same line)
    let (trailingOpt, childComments) =
        let sameLine = remaining |> List.tryFind (fun c -> c.Pos.Line = exprLine)
        let rest = remaining |> List.filter (fun c -> c.Pos.Line <> exprLine)
        (sameLine, rest)

    // 3. Format leading comments
    let leadingStr =
        leading
        |> List.sortBy (fun c -> c.Pos.Line)
        |> List.map (fun c -> sprintf "%s//%s\n" spaces c.Text)
        |> String.concat ""

    // 4. Format expression (recursively handle child comments)
    let exprStr = formatExpr indent expr trailingOpt childComments

    leadingStr + exprStr

Example

Input
// comment1
let x = 1
// comment2
let y = 2  // trailing
x + y
Comment Matching
comment1 (line 1) → Leading for `let x` (line 2)
comment2 (line 3) → Leading for `let y` (line 4)
trailing (line 4) → Trailing for `let y` (line 4)
Output (Preserved)

// comment2
