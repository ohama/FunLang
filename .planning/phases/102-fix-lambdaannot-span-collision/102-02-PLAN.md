Add a new test `TA-08` to the `typeAnnotationTests` test list in TypeAnnotationTests.fs, inserted after TA-07 and before the closing `]`.

The test input MUST use the `let` declaration form (not bare `fun`), because multi-param let declarations trigger `desugarAnnotParams`/`desugarMixedParams` which produce nested LambdaAnnot nodes:

```
let f (x : int) (y : string) (z : bool) : int = 42
```

Follow the EXACT pattern of existing TA-01..TA-07 tests:
1. Call `typeCheckAndSnapshot` with the input string.
2. Use `annots |> Map.toSeq` to inspect results.
3. Count distinct `TArrow` entries in the annotationMap:

```fsharp
test "TA-08: multi-param annotated let has distinct spans per LambdaAnnot" {
    let input = "let f (x : int) (y : string) (z : bool) : int = 42"
    let annots = typeCheckAndSnapshot input
    // Each LambdaAnnot should produce a distinct annotationMap entry with TArrow type
    // Outermost: int -> string -> bool -> int
    // Middle: string -> bool -> int
    // Innermost: bool -> int
    let arrowEntries =
        annots
        |> Map.toSeq
        |> Seq.filter (fun (_, ty) ->
            match ty with
            | Type.TArrow _ -> true
            | _ -> false)
        |> Seq.toList
    // There should be at least 3 distinct TArrow entries (one per annotated param)
    Expect.isTrue (arrowEntries.Length >= 3)
        (sprintf "Should have at least 3 TArrow entries for 3 annotated params, got %d" arrowEntries.Length)
    // All spans should be distinct (no collisions)
    let spans = arrowEntries |> List.map fst
    let distinctSpans = spans |> List.distinct
    Expect.equal distinctSpans.Length spans.Length
        "All TArrow spans should be distinct (no span collisions)"
}
```

Do NOT write a custom `collectLambdaAnnotSpans` helper -- the existing `collectSpans` function already covers LambdaAnnot nodes (line 63). Instead, rely on the annotationMap itself: after the fix, distinct LambdaAnnot nodes will have distinct spans, producing distinct TArrow entries in the map.
