**1a. Add operator definitions to Prelude/Core.fun** (inside `module Core = ...`, before `open Core`):

```
    #[left 1]
    let (|>) x f = f x
    #[right 2]
    let (>>) f g = fun x -> g (f x)
    #[left 2]
    let (<<) f g = fun x -> f (g x)
```

Fixity rationale: `|>` at prec 1, `>>`/`<<` at prec 2. These are both below the
default INFIXOP0 prec of 4, so within INFIXOP0 chains, `|>` binds less tightly than
any other INFIXOP0 operator, and `>>`/`<<` bind less tightly than everything except `|>`.
This preserves the relative ordering: pipe < compose < comparison-level operators.

Note: `>>` is right-assoc (f >> g >> h = f >> (g >> h)) and `<<` is left-assoc
(f << g << h = (f << g) << h). This matches the current parser %left/%right declarations.

IMPORTANT: Remove the existing `let compose f = ...` definition since `>>` replaces it.
Keep it if any tests reference `compose` directly (grep first).

**1b. Remove special lexer rules from Lexer.fsl:**

Delete these 3 lines (around lines 128-130):
```

    | ">>"          { COMPOSE_RIGHT }
    | "<<"          { COMPOSE_LEFT }
```

After removal, `|>`, `>>`, `<<` will fall through to the catch-all rule
`| op_char op_char+ { classifyOperator (lexeme lexbuf) }` (line 170).

(`|`, `>`, `<` all map to INFIXOP0).
