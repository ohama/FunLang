  <name>Task 1: Untag integer args before C calls, retag integer results after C calls</name>
  <files>src/FunLangCompiler.Compiler/Elaboration.fs, src/FunLangCompiler.Compiler/ElabHelpers.fs</files>
  <action>
This task adds `emitUntag` before C calls that receive tagged integer arguments, and `emitRetag` after C calls that return raw integer results. Use `emitUntag`/`emitRetag` from ElabHelpers.fs.

IMPORTANT PRINCIPLE: Only untag values that the C function interprets as integers. Values that are just "passed through" (stored/returned as opaque i64) do NOT need untag because they'll already be tagged from the user side.

### A. Fix emitVoidCall unit constant (ElabHelpers.fs)

In `emitVoidCall` (~line 346-348), change `ArithConstantOp(unitVal, 0L)` to `ArithConstantOp(unitVal, 1L)` (tagged unit = tagged 0 = 1). This fixes ALL void-call unit results at once (write_file, eprint, hashtable_remove, queue_enqueue, mutablelist_add, mutablelist_set, index_set, etc.).

### B. C calls that need UNTAG on integer args

For each site below, wrap the tagged I64 argument with `emitUntag` before passing to the C function. Pattern:
```fsharp
let (rawArg, untagOps) = emitUntag env taggedArg
// ... include untagOps in the op list, use rawArg in the call
```

1. **lang_to_string_int** (~lines 1001, 1073): Untag `argVal` before calling.
   - At ~line 1001: `(result, argOps @ untagOps @ [LlvmCallOp(result, "@lang_to_string_int", [rawArg])])`
   - At ~line 1073: same pattern
   - At ~line 1740/1742 (dbg): untag before `lang_to_string_int`

2. **lang_to_string_bool** (~lines 993, 995, 1063, 1066): The I1 branch goes through ArithExtuIOp which now retags (from Plan 01). So the value passed to `lang_to_string_bool` will be tagged (1 or 3). C expects 0 or 1. Untag before calling.
   - At ~line 993: after ArithExtuIOp (now produces tagged), untag before call
   - At ~line 995: argVal is I64 (known bool, could be tagged 1 or 3), untag before call
   - At ~line 1063, 1066: same patterns

3. **lang_string_sub(strPtr, startVal, lenVal)** (~line 854): Untag `startVal` and `lenVal`.

4. **lang_range(startVal, stopVal, stepVal)** (~line 2395): Untag all three args.

5. **lang_array_create(nV, defV)** (~line 1164): Untag `nV` only (it's the count). Do NOT untag `defV` — it's a user value stored as-is.

6. **lang_array_bounds_check(arrPtr, idxVal)** (~lines 1121, 1141): Untag `idxVal`.

7. **lang_string_char_at(collPtr, idxV)** (~line 1257): Untag `idxV`.

Since we can't always tell, untag unconditionally — hashset values are compared, so they must be consistent. Actually, since ALL user values are now tagged, and the C hashset uses raw comparison, we must untag before add/contains to keep C-side consistent. Untag `valVal`.
