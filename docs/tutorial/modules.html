Module System

FunLang's module system allows you to organize code into reusable units with explicit exports and qualified access.

Module Basics

Defining a Module

Modules are defined using the module keyword:

Basic module
module Math =
  export add, multiply

  let add = fun x -> fun y -> x + y
  let multiply = fun x -> fun y -> x * y

Math.add 2 3
=> 5

Module Structure

A module consists of:

  • Name: Module names start with uppercase (e.g., Math, Utils)
  • Export list: Declares which items are publicly accessible
  • Body: Contains let bindings and type definitions
module ModuleName =
  export item1, item2, ...   // export declaration

  let item1 = ...            // exported
  let item2 = ...            // exported
  let helper = ...           // private (not exported)

Exports

Export Declaration

The export keyword lists items that are publicly accessible:

Public and private items
module Utils =
  export double, square    // only these are public

  let double = fun x -> x * 2      // public
  let square = fun x -> x * x      // public
  let helper = fun x -> x + 1      // private

Utils.double 5
=> 10
Note
Items not in the export list are private to the module. Attempting to access them from outside will result in an error.

Multiple Exports

Exporting multiple items
module Calculator =
  export add, subtract, multiply, divide

  let add = fun x -> fun y -> x + y
  let subtract = fun x -> fun y -> x - y
  let multiply = fun x -> fun y -> x * y
  let divide = fun x -> fun y -> x / y

Calculator.subtract 10 3
=> 7

Qualified Names

Accessing Module Members

Use dot notation to access exported module members:

// ModuleName.memberName
Math.add 1 2
Utils.double 5
Calculator.multiply 3 4

Multiple Modules

You can define and use multiple modules in the same file:

Multiple modules
module Math =
  export square

  let square = fun x -> x * x

module Utils =
  export double

  let double = fun x -> x * 2

// Use functions from both modules
Math.square (Utils.double 3)
=> 36

Combining Module Functions

Using modules together
module Math =
  export add, multiply

  let add = fun x -> fun y -> x + y
  let multiply = fun x -> fun y -> x * y

module Utils =
  export double

  let double = fun x -> x * 2

// Compute: (2 + 3) * double(4) = 5 * 8 = 40
Math.multiply (Math.add 2 3) (Utils.double 4)
=> 40

Recursive Functions in Modules

Modules support recursive functions with let rec:

Recursive module function
module Math =
  export factorial, fibonacci

  let rec factorial = fun n ->
    if n <= 1 then 1
    else n * factorial (n - 1)

  let rec fibonacci = fun n ->
    if n <= 1 then n
    else fibonacci (n - 1) + fibonacci (n - 2)

(Math.factorial 5, Math.fibonacci 10)
=> (120, 55)

Practical Example: String Utilities

String module
module StringUtils =
  export greet, exclaim

  let greet = fun name -> "Hello, " ^ name ^ "!"
  let exclaim = fun s -> s ^ "!!"

StringUtils.greet "FunLang"
=> "Hello, FunLang!"

Best Practices

Module Design Tips
  • Explicit exports: Only export what needs to be public
  • Meaningful names: Use descriptive module and function names
  • Single responsibility: Each module should have a focused purpose
  • Helper functions: Keep implementation details private

Good Module Design

// Good: focused module with clear exports
module ListOps =
  export map, filter, fold

  // Public API
  let rec map = fun f -> fun xs -> ...
  let rec filter = fun pred -> fun xs -> ...
  let rec fold = fun f -> fun acc -> fun xs -> ...

  // Private helpers
  let helper1 = ...
  let helper2 = ...

Current Limitations

v0.5.0 Limitations

The current module system (Phase 1 MVP) has some limitations:

  • No nested modules: Modules cannot contain other modules
  • Single file only: Modules must be in the same file as the code that uses them
  • No open/import: Cannot import modules into current scope
  • No self-reference: Module functions cannot call other functions from the same module using qualified names

These features are planned for future versions.
